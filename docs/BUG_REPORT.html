5. Comprehensive Bug List & Fix Prompts

B-001: GET /api/v1/reports crashes with HTTP 503 on stale on-chain deployments
BLOCKER Codex (Backend)

Evidence: GET /api/v1/reports?risk=suspicious returns HTTP 503 chain_unavailable when reports reference previously deployed contracts.

Root Cause: current_report() in app/web3/registry.py:148 eagerly calls observed() for every report with a receipt. If that contract address does not exist on the active chain, it raises ChainUnavailable, crashing the entire listing.

Expected: Wrap observed() in try/except ChainUnavailable and fall back to read_report(row).

REPO CONTEXT: origin https://github.com/himeshghosh98-maker/THREAT, folder wt-backend, branch backend-dev, edits in backend/ only. Run git pull and git merge main. Commit message: "fix B-001: handle chain unavailable gracefully in current_report". Push to backend-dev.
BUG: GET /api/v1/reports crashes with HTTP 503 when any report was published on a previous local chain deployment.
IN backend/app/web3/registry.py, in current_report(row, settings), wrap the observed(row, settings)[0] call in a try/except ChainUnavailable block: on exception, return read_report(row).
DO NOT change API contract shapes, SSRF checks, or publish/verify routes.
REGRESSION TEST: Add a test in tests/test_c4.py verifying list_reports returns 200 when a report in DB has a stale contract address.
Print only commit hash and a 3-line summary.
B-002: Oversensitive classification threshold flags benign domains as suspicious
BLOCKER Codex (Backend)

Evidence: Scanning github.com or google.com returns score 8 and classification suspicious.

Root Cause: app/core/risk.py:16 sets suspicious whenever score >= WEIGHTS["info"] (score >= 2). A single informational indicator triggers a false positive.

Expected: Scores < 30 should be low_risk (or inconclusive if checks failed); require score >= 30 for suspicious.

REPO CONTEXT: origin https://github.com/himeshghosh98-maker/THREAT, folder wt-backend, branch backend-dev, edits in backend/ only. Run git pull and git merge main. Commit message: "fix B-002: adjust suspicious risk score threshold". Push to backend-dev.
BUG: Benign domains with minor DNS/header indicators (score 8) are classified as suspicious because threshold is score >= WEIGHTS["info"] (2).
IN backend/app/core/risk.py: change condition to elif score >= 30: classification = "suspicious". For scores < 30, classify as "inconclusive" if failed or not completed, else "low_risk".
DO NOT change indicator weights or confirmed_malicious rules.
REGRESSION TEST: Ensure score_risk([], ["DNS"], []) returns low_risk and score_risk([Indicator(..., severity='low')], ["DNS"], []) returns low_risk.
Print only commit hash and a 3-line summary.
B-003: Unhandled NXDOMAIN in dns_answer breaks safe_resolve

Evidence: Resolving AAAA records on domains without IPv6 throws NXDOMAIN, causing safe_resolve and all outbound HTTP/TLS checks to fail.

Root Cause: app/core/ssrf.py:65 does not catch NXDOMAIN or NoAnswer during dns.asyncresolver.resolve().

Expected: Catch DNS exceptions and return [] so IPv4 A records are used successfully.

REPO CONTEXT: origin https://github.com/himeshghosh98-maker/THREAT, folder wt-backend, branch backend-dev, edits in backend/ only. Run git pull and git merge main. Commit message: "fix B-003: catch NXDOMAIN in ssrf dns_answer". Push to backend-dev.
BUG: safe_resolve crashes with NXDOMAIN on domains lacking AAAA records, breaking safe_fetch and TLS checks.
IN backend/app/core/ssrf.py, in dns_answer(host, record), wrap the dns.asyncresolver.resolve call in try/except (dns.resolver.NXDOMAIN, dns.resolver.NoAnswer, dns.exception.DNSException): and return [].
DO NOT remove public_ip validation or SSRF ipaddress checks.
REGRESSION TEST: Verify safe_resolve resolves domains having only IPv4 A records without throwing NXDOMAIN.
Print only commit hash and a 3-line summary.

7. Not-Bugs & Demo Risk Disclosures

  • Unconfigured API Keys: Missing Google Safe Browsing and LLM provider keys trigger deterministic offline fallbacks. This is an intended architecture feature, not a bug.
  • Rate Limiting (10 req/min): Bursts exceeding 10 scans receive HTTP 429 rate_limited. Presenters must space live scan demonstrations by ~6 seconds.
  • Hardhat Node Reset: Restarting the local node clears chain state. Always execute start_local_chain.ps1 before launching uvicorn.
